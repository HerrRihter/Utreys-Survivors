# Журнал забегов и статистика баланса

Раздел «Как проверять результат» плана улучшения.

## Журнал

Каждое завершение забега добавляет запись в `localStorage` (`utreys-run-log-v1`, последние
300 записей). Код — `src/systems/run-log.js`. Поля записи:

| Поле | Что это |
| --- | --- |
| `hero`, `map`, `load`, `seed` | Герой, карта, нагрузка, сид |
| `win`, `endless`, `time`, `productionTime` | Итог, продакшен, длительность |
| `cause` | Юнит, нанёсший последний удар; `quit` — выход в меню; `null` — победа |
| `level`, `kills`, `nodes`, `events` | Уровень, победы, статусы узлов, выполненные события |
| `damage` | Урон по источникам (`hero`, умения, оружие, `bomb`) |
| `build` | Оружие и пассивки с уровнями |
| `offers` | Левелапы: показанные карточки, взятая (`picked`), `pick` / `skip`, рероллы, баны |
| `learning` | Учебный забег: курс, оценка, ответы по темам (иначе `null`) |
| `incident` | Смена режима эскалации: версия правил, оценка и доля, баллы групп, вопросы курса с ошибками и их число, сбои, тикеты, ложные эскалации, вводные, обвал, отвеченные вопросы разбора (иначе `null`). Без текстов |

Продолжение в продакшене даёт вторую запись с `endless: true` и только своими левелапами,
поэтому карточки не считаются дважды.

Экспорт и очистка — «Настройки» → «Журнал забегов»; карточка видна только с `?dev` в адресе (игрокам она не нужна, журнал пишется всегда). Файл:
`{ "format": "utreys-run-log", "version": 3, "runs": [...] }`. Записи старых сборок читаются
с текущими полями (версия 1 получает `learning: null`, версия 2 — `incident: null`) и
текущими id карточек (`normalizeLogEntry` в `src/systems/run-log.js`, им же пользуется
`tools/run-stats.cjs`): `ability_potion` считается как `ability_overclock`.

## Статистика

```bash
npm run stats -- utreys-runs-2026-10-16.json другой-игрок.json
```

Скрипт `tools/run-stats.cjs` принимает несколько файлов и выводит:

- долю взятий каждой карточки от её показов; отмечает больше 70% и меньше 5% (оценка
  начинается с 10 показов, порог меняет `--min N`);
- забеги, победы и долю побед по герою и нагрузке; отмечает, если на одной нагрузке доли
  побед героев (с 5 забегами и больше) расходятся больше чем в 1,5 раза;
- частые причины поражений и долю урона по источникам; лучшее время в продакшене.

Учебные забеги и смены режима эскалации в баланс не входят: `computeStats` возвращает их
отдельно (`learning`, `incident`).

Сводка смены записывается при её завершении. Каждый ответ разбора PIR обновляет `incident`
в той же записи: после разбора оценка совпадает с экраном итогов, новый забег не добавляется.
Если игрок ушёл без разбора, остаётся сводка с числом уже отвеченных вопросов (`reviewed`).

`--json` выводит те же данные машиночитаемо.
