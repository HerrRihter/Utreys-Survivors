# Фризы при большом числе врагов — 16 октября 2026

Сценарий пользователя: Firefox, телефонный размер окна, много врагов.
Просадка воспроизведена в отдельном headless Firefox 157.0 на Windows,
с production-сборкой, окном 390×844 и deviceScaleFactor=2.
Это настольный Firefox с узким viewport, не измерение на физическом телефоне
и не профиль пользовательского Firefox с его настройками GPU и расширениями.

## Проверки

- `npm test`: 28/28 наборов, включая контракты структуры и ресурсов.
- `npm run lint`: ESLint и TypeScript прошли.
- `npm run format:check`: прошёл.
- `npm run build`: прошла production-сборка.
- `BROWSER_CHANNEL=msedge npm run test:browser`: оба URL (`/` и
  `/utreys-survivors/`), навигация, игровая сессия, аудио, ресурсы и ширины прошли.
- `npm run benchmark`: 300 секунд обычных волн и 60 секунд стресса с 300 врагами.
  В Node стрессовая симуляция: p95 0,73 мс, p99 1,01 мс, максимум 2,40 мс.
  Это стоимость симуляции в V8 с заглушками Canvas/аудио, не FPS Firefox.

## Воспроизведение

Первый 35-секундный прогон Firefox, DPR 2, без фиксированного seed:

| Врагов | RAF FPS | JS, медиана | JS, p95 | JS, максимум | Интервал >50 мс |
| --- | ---: | ---: | ---: | ---: | ---: |
| 50 | 60,0 | 10 мс | 13 мс | 24 мс | 0 |
| 300 | 35,1 | 28 мс | 37 мс | 52 мс | 45 |

Полные результаты: [render.json](render.json). Время симуляции продвинулось
примерно на 35 секунд в обоих случаях: тест не застрял на экране улучшения.
При 60 Гц бюджет кадра — 16,7 мс. При 300 врагах даже медианный callback
превышает этот бюджет; задержки воспроизводятся без ошибок JavaScript.

Короткий диагностический прогон с инструментированием Canvas (300 врагов,
DPR 2, 8 секунд измерения плюс прогрев) дал суммарно:

- `drawImage`: 4805 мс, 240789 вызовов;
- `fillRect`: 2404 мс, 33074 вызова;
- `fill`: 720 мс; `stroke`: 502 мс;
- `getTransform`: 58 мс.

Инструментирование добавляет накладные расходы и включает прогрев/меню;
это ориентир для локализации затрат, а не чистые времена игрового кадра.
Основной подтверждённый узкий участок этого воспроизведения — отрисовка Canvas.
В `src/entities/enemies.js` для каждого видимого врага отдельно рисуются
кэшированный спрайт и подпись. При скоплении врагов число этих операций растёт.
`src/rendering/scene-renderer.js` также рисует тени, телеграфы, эффекты и заливки.
Кэш спрайтов уже существует; его наличие не делает вывод сотен спрайтов бесплатным.

`src/rendering/canvas.js` допускает DPR до 2: для 390×844 это backing canvas
780×1688, то есть вчетверо больше пикселей, чем при DPR 1. Портретный zoom 0,9
меняет охват мира, но не уменьшает итоговое число пикселей backing canvas.
Контрольные 35-секундные прогоны с seed=123456 сохранены отдельно:
[DPR 1](firefox-portrait-dpr1.json) и [DPR 2](firefox-portrait-dpr2.json).
При 300 врагах DPR 2 дал 34,1 FPS и p95 callback 38 мс;
DPR 1 — 48,8 FPS и p95 25 мс. Интервалов >50 мс: 60 против 5.
Снижение DPR помогает, но само по себе не гарантирует 60 FPS при 300 врагах.

## Что изменено

Расширен `tools/benchmark-render.cjs`:
Firefox и Edge, viewport, DPR, длительность, число врагов, фиксированный seed,
интервалы RAF и продвижение игрового времени. Улучшения автоматически выбираются,
чтобы длинный замер не продолжался на остановленной симуляции.

Старый бенчмарк запускал только Chromium, 1280×720, DPR 1, без ограничения RAF
и без измерения интервалов между кадрами. Его высокий FPS не исключал этот дефект.
Новый FPS тоже означает частоту RAF, а не подтверждённые отображения на дисплее.

Команда воспроизведения в PowerShell после `npm.cmd run build`:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/test-results/playwright"
npx.cmd playwright install firefox
$env:BROWSER = 'firefox'
$env:BENCH_WIDTH = '390'
$env:BENCH_HEIGHT = '844'
$env:BENCH_DPR = '2'
$env:BENCH_SECONDS = '35'
$env:BENCH_COUNTS = '300'
$env:BENCH_OUTPUT = 'test-results/firefox-render.json'
npm.cmd run benchmark:render
```

Для контрольного прогона поменять `BENCH_DPR` на `1`. Сравнивать последовательно,
не запускать параллельно другие нагрузочные тесты.

## Исправление без снижения качества

В портретном режиме при DPR 2 фактический transform равен 1,8. Раньше тела врагов
и пол кэшировались в масштабе 1,75 (округление до четверти), а подписи — всегда в 2.
Firefox приходилось повторно масштабировать эти изображения при каждом выводе.
Даже округление размера backing canvas вверх создавало небольшое дополнительное
масштабирование, когда его целиком вписывали в прежний логический размер.

- Тела врагов, подписи и плитка пола теперь кэшируются в фактическом масштабе
  контекста, включая портретный zoom и увеличенных элитных врагов.
- Размер вывода тела/подписи равен числу backing-пикселей, делённому на масштаб:
  исходные пиксели копируются без повторного изменения размера.
- Из кэша тела удаляются только полностью прозрачные поля. Сохраняются даже
  пиксели свечения с alpha=1, и компенсируется смещение обрезанного изображения.
- DPR, размер игрового Canvas, эффекты, подписи, анимации и количество врагов
  не уменьшены. Растризация в точном масштабе меняет антиалиасинг относительно
  прежнего растянутого кэша; финальный результат не заявляется побитово идентичным.
  Визуально проверены все 21 тип противников при масштабе 1,8 — детали сохранены.

Одинаковый стресс-сценарий: Firefox 157.0 headless, 390×844, DPR 2, seed=123456,
300 врагов, 35 секунд после прогрева:

| Метрика | До | После |
| --- | ---: | ---: |
| RAF FPS | 34,1 | 52,1 |
| JS, медиана | 29 мс | 17 мс |
| JS, p95 | 38 мс | 27 мс |
| Максимальный интервал кадров | 50,04 мс | 33,38 мс |
| Интервалы >50 мс | 60 | 0 |

Результат: [firefox-portrait-fixed.json](firefox-portrait-fixed.json).
Ускорение примерно 53%; устойчивые 60 FPS при 300 врагах не гарантируются.
Это результат указанного стенда, не гарантия частоты кадров на любом телефоне.

После исправления прошли `npm run check` (29/29 наборов тестов, ESLint,
TypeScript, форматирование и production-сборка) и браузерные smoke-проверки
в Firefox и Edge на обоих URL. `tests/test-sprite-cache.cjs` проверяет сохранение
слабого свечения, повторное использование кэша и отсутствие ресэмплинга тел и
подписей при масштабах 0,9 / 1 / 1,8 / 2 / 2,34.

Браузерные проверки Firefox: задать `BROWSER=firefox` и тот же
`PLAYWRIGHT_BROWSERS_PATH`, затем выполнить `npm.cmd run test:browser`.
