# Как самостоятельно добавить персонажа

Рабочая версия: `D:\Utrace\scripts\gaul-survivors\preserve-version`.

Схема: **рисунки → реестр анимаций → параметры → доступность → поведение → проверка**.

Графика уже подключается через данные. Уникальные способности пока частично привязаны к ID в JavaScript. Поэтому новый обычный боец ближнего боя добавляется проще, чем новый метатель или маг. Ниже — полный минимальный пример героя `bravix` («Бравикс») с обычным ударом, без личных улучшений. Он не добавлен в игру автоматически: это инструкция для самостоятельного изменения.

## 1. Подготовить рисунки

Выберите один постоянный ID латиницей: `bravix`. Используйте его одинаково в именах папок, реестре, параметрах и магазине. Не используйте пробелы и кириллицу в ID; отображаемое имя может быть русским.

Каждый кадр — отдельный PNG размером **256×256**, прозрачный фон, направление вправо. Точка опоры — **(128, 236)**. При развороте игра зеркалит рисунок сама.

Для обычного героя ориентируйтесь на высоту тела 80–90 px. Для сравнения: Астерикс — 64, Обеликс — 90. Не увеличивайте рисунок до размера всего PNG. Для совместимости с текущими портретами желательно держать всю позу с оружием в пределах `x=72…184`, `y=132…235`. Более широкие позы могут потребовать изменения области портрета в `src/ui/menu-portraits.js`; размер коллизии от размера рисунка не меняется.

Сначала нарисуйте одну эталонную стойку. На её основе создайте движения: размер головы, ширина туловища и масштаб одежды должны оставаться согласованными. Не масштабируйте каждый кадр отдельно по полной высоте силуэта: поднятая рука или оружие увеличивают эту высоту естественно. Убедитесь, что стойка, ходьба и окончание атаки сохраняют одинаковый рост, а ноги стоят на одной линии.

Для первого персонажа достаточно 12 изображений:

```text
assets/runtime/characters/heroes/bravix/animations/
  walk/
    0.png
    1.png
    2.png
    3.png
  attack/
    0.png
    1.png
    2.png
    3.png
  hurt/
    0.png
    1.png
    2.png
    3.png
```

В атаке: 0 — подготовка, 1 — замах, 2 — удар, 3 — возврат в стойку. Игра наносит урон на 50% длительности атаки — при четырёх равных кадрах это начало кадра 2. Кадры анимации могут иметь другое количество, но момент урона от этого не меняется. Последний кадр атаки сделайте удобным для состояния покоя.

При генерации изображений используйте один эталон персонажа для всех поз. В запросе явно укажите одинаковые пропорции, одежду, вид сбоку вправо, прозрачный фон и отдельный кадр. Точную укладку в 256×256 и положение стоп проверяйте после генерации в графическом редакторе.

## 2. Зарегистрировать анимации

Откройте `data/animations/character-frames.json`. Добавьте запись внутрь объекта `characters` рядом с другими персонажами; между соседними записями нужна запятая. JSON не поддерживает комментарии и запятую после последнего поля.

```json
"bravix": {
  "renderer": "villager",
  "actions": {
    "walk": [
      "characters/heroes/bravix/animations/walk/0.png",
      "characters/heroes/bravix/animations/walk/1.png",
      "characters/heroes/bravix/animations/walk/2.png",
      "characters/heroes/bravix/animations/walk/3.png"
    ],
    "attack": [
      "characters/heroes/bravix/animations/attack/0.png",
      "characters/heroes/bravix/animations/attack/1.png",
      "characters/heroes/bravix/animations/attack/2.png",
      "characters/heroes/bravix/animations/attack/3.png"
    ],
    "hurt": [
      "characters/heroes/bravix/animations/hurt/0.png",
      "characters/heroes/bravix/animations/hurt/1.png",
      "characters/heroes/bravix/animations/hurt/2.png",
      "characters/heroes/bravix/animations/hurt/3.png"
    ]
  },
  "idle": {"action": "attack", "index": 3}
}
```

Пути в этом JSON начинаются от `assets/runtime/`, поэтому этот префикс не пишется повторно. Для нового героя используйте `villager`, для обычного нового врага — `unit`. Адаптер `animation` обслуживает существующие базовые наборы Астерикса, Обеликса и римлян.

Обычный персонаж не требует `actionScale`. Если исходная атака целиком нарисована мельче ходьбы, можно добавить, например, `"actionScale": {"attack": 1.1}`: коэффициент применяется ко всей последовательности один раз при загрузке. Не копируйте поправку Обеликса без измерения собственных кадров.

Не редактируйте `data/animations/character-frames.js` и `runtime/` вручную: это генерируемые копии.

## 3. Добавить параметры героя

В `data/characters/heroes.js` добавьте внутрь `heroDefinitions`:

```js
bravix: {
  name: 'Бравикс',
  hp: 120,
  speed: 145,
  interval: 0.85,
  wind: 0.5,
  damage: 32,
  half: Math.PI / 3,
  weapon: '✦ БОЕВАЯ ДУБИНА',
  desc: '120 HP. Удар дубиной: 32 урона в секторе 120°.'
},
```

| Параметр | Значение |
| --- | --- |
| `hp` | Базовое здоровье до постоянных улучшений |
| `speed` | Скорость движения в логических пикселях в секунду |
| `interval` | Интервал между началами атак в секундах, до ускорений |
| `wind` | Полная длительность анимации атаки в секундах; удар происходит на её середине |
| `damage` | Базовый урон обычного удара |
| `half` | Половина угла сектора в радианах; `Math.PI/3` даёт полный сектор 120° |
| `weapon`, `desc` | Текст интерфейса; сами по себе не задают механику |

Для этого примера не ставьте `passive: true`: этот флаг отключает обычную автоматическую атаку. Длительность `wind` желательно делать не больше `interval`.

## 4. Добавить в лавку и обеспечить загрузку

В `src/systems/persistence.js` найдите объект `prices` и добавьте `bravix: 75`. Герой появится в лавке автоматически; после покупки он появится в выборе перед забегом. Сохранение покупки также заработает: новые ID из `prices` уже допускаются при чтении сохранений.

Для первого теста можно временно поставить цену **0**, затем купить героя в лавке. Само наличие цены 0 не делает его автоматически купленным. После проверки верните цену 75. Уже купленный герой останется открыт в вашем сохранении.

В `src/entities/heroes.js` найдите объект `colors` и добавьте:

```js
bravix: ['#607c4b', '#a66334'],
```

Это цвета простого резервного рисунка. Он нужен, пока PNG загружаются или если файл не найден. Без такой записи новый герой может попасть в существующую ветку отрисовки без резервного спрайта, особенно при раннем открытии лавки.

Отдельный файл портрета новому герою с `renderer: 'villager'` не требуется: меню рисует портрет из игровых кадров.

## 5. Понять, какая атака заработает

В приведённом примере герой получит обычный секторный удар: текущая общая ветка `heroImpact` в `src/systems/combat.js` использует `damage` и `half` из параметров. Его базовая дальность — 70 px с учётом общих усилений. Общие улучшения урона, темпа, радиуса и здоровья уже работают; личных улучшений у этого минимального героя пока нет.

Имена оружия или копирование параметров Обеликса не включают метание менгиров. Специальные способности проверяют конкретные ID. Для новой механики нужны изменения:

| Что добавить | Где менять |
| --- | --- |
| Эффект в момент удара: снаряд, взрыв, специальный ближний удар | `src/systems/combat.js`, функция `heroImpact` |
| Постоянная аура, след, обновление собственных снарядов | `src/entities/heroes.js`, функция `update`, либо отдельная система |
| Личные улучшения в забеге | `src/systems/upgrades.js`, объект `heroes` и обработка соответствующих характеристик в механике |
| Личное постоянное улучшение в лавке | `training` в `src/systems/persistence.js` и применение в `permanent` в `src/systems/upgrades.js` |

Не копируйте личные улучшения другого героя вслепую: некоторые бонусы проверяются по его конкретному ID. Запись бонуса в интерфейсе не гарантирует, что боевая логика его применяет.

## 6. Сгенерировать, проверить и запустить

Откройте PowerShell в папке проекта и выполните:

```powershell
Set-Location 'D:\Utrace\scripts\gaul-survivors\preserve-version'
npm run generate
npm test
npm run build
npm start
```

Проверяйте код возврата и вывод каждой команды; при ошибке исправьте её до перехода к следующему шагу. `npm start` оставляет сервер работающим; для остановки нажмите Ctrl+C.

- Игра: `http://127.0.0.1:8765/`.
- Все кадры, включая нового персонажа из реестра: `http://127.0.0.1:8765/previews/animation-audit.html`.
- `animation-preview.html` пока содержит фиксированный список старых героев; новый герой автоматически появляется в **animation-audit**, а не в этом старом просмотрщике.

В браузере проверьте покупку, выбор, начало забега, ходьбу в обе стороны, переход в покой, попадание атакой, получение урона и повторное открытие после перезагрузки. Сравните размер тела между ходьбой, стойкой и атакой; поднятое оружие не должно быть поводом уменьшать персонажа. В консоли браузера не должно быть ошибок или 404 для PNG.

Тесты проверяют файлы и общую механику, но новую уникальную способность нужно дополнительно проверить в бою и покрыть тестом её эффекта. В `tests/test-upgrades.cjs` сейчас ожидается по три личных ветки для каждого героя, зарегистрированного в `UpgradeSystem.heroes`: учитывайте это, если добавляете личные улучшения.

Новые кадры из JSON входят в сборку автоматически; вручную перечислять их в `tools/publication-manifest.cjs` не нужно. После `npm run generate` сохраняйте в Git исходники **и обновлённые генерируемые JS-файлы**. Папка `_site/` создаётся при сборке и не коммитится.

## Если нужен новый враг

Рисунки и структура реестра те же, но `renderer` — `unit`, а кадры находятся в `assets/runtime/characters/enemies/<id>/animations/<action>/`. Добавьте параметры в `data/enemies/units.js` и правило появления в `data/enemies/waves.js`.

Пример обычного врага ближнего боя:

```js
// Внутри unitDefinitions:
guard: {name:'Стражник',hp:100,speed:45,damage:14,r:13,
  range:42,wind:0.8,cooldown:1.5,xp:2,color:'#b9c8d5',mark:'G'},

// В начале массива waves.units:
{type:'guard',time:40,cutoff:0.1,message:'СТРАЖНИКИ · Тяжёлая пехота.'},
```

`cutoff` — порог общего случайного числа, а не независимый процент для каждой записи. Выбирается **первая** подходящая запись массива. Пример в начале массива отдаёт стражникам 10% обычных появлений после 40-й секунды и меняет доли следующих типов. Проверяйте порядок и баланс волн.

При обычном новом ID враг использует общую ближнюю атаку. Копирование характеристик пилума или тарана не копирует их особое поведение: оно привязано к ID в `src/systems/simulation.js` и других системах. Смерть, опыт и отрисовка обычного нового отряда используют данные `unitDefinitions` и `UnitArt`.

Самый простой первый шаг — заменить PNG у уже существующего героя, сохранив ID и пути. Затем добавить описанного выше бойца; новую уникальную способность лучше делать после проверки графики и базовой механики.
