# Микрофризы: причины и исправления

Дата: 12 октября 2026.

## Подтверждённые причины

1. **Растеризация дороги в лагере.** При создании кэша земли 15 000 эллипсов и штрихи колеи рисовались по одному под сложной маской всех дорог. JS только ставил операции в очередь, поэтому обычный CPU-профиль показывал короткий `draw()`, хотя растеризация задерживалась. В отдельной Chromium-трассировке `RasterDecoderImpl::DoRasterCHROMIUM` занял 1525 мс. После переноса деталей на промежуточную поверхность с однократной обрезкой готового слоя самая долгая такая операция в повторной трассировке — 28,7 мс. Самая долгая задача GPU-потока сократилась с 1719 до 99 мс. Это измерения разных вложенных операций, их нельзя складывать или приравнивать к интервалу кадра.
2. **Интерфейс умений менял DOM каждый кадр.** Записи `textContent`, `title`, `disabled` выполнялись даже при неизменных значениях. Теперь значения сравниваются перед записью, узлы сохраняются, видимость меняется только при необходимости. Отсчёт активного эффекта остаётся с точностью до десятых секунды.
3. **Избыточная работа HUD.** Чтение `Progression.data` полностью сериализовало и копировало сохранение ради числа шлемов и ранга брони. Добавлены точечные read-only getters. Дробная регенерация больше не пересоздаёт неизменный текст HP: число округляется как раньше, полоса обновляется с точностью 0,1%.
4. **Работа в боевом кадре, которую можно избежать.** Повышение ранга брони использует существующую очередь сохранения с записью в idle и принудительной записью при паузе/выходе/скрытии страницы. Убраны копирование характеристик без активных модификаторов, копия состояния ради музыкальной ауры и создание полей контроля при атаках без контроля.

Геометрия дорог, все 15 000 деталей, столкновения, количество противников, эффекты умений и баланс сохранены. Для построения дороги используется одна дополнительная временная поверхность 2200×2200 (около 19,4 MB RGBA); она не создаётся заново в каждом кадре. Готовая земля продолжает использовать существующий кэш.

## Замеры до и после

Headless Microsoft Edge, окно 1920×1080, реальный RAF, Автоматикс, 120 смешанных противников, движение и применение умений, 600 кадров на арену (599 интервалов). Включены CPU sampling, MutationObserver кнопок и счётчики layout/style. В отдельном контексте браузера используются тестовые сохранения.

| Арена | Изменения DOM кнопок: до → после | Layout всей страницы: до → после | Максимальный интервал кадра: до → после | Интервалы >33,4 мс: до → после |
| --- | ---: | ---: | ---: | ---: |
| Деревня | 3609 → 50 | 601 → 52 | 18,5 → 16,9 мс | 0 → 0 |
| Лес | 3609 → 50 | 601 → 51 | 33,3 → 16,9 мс | 0 → 0 |
| Лагерь | 3609 → 50 | 600 → 51 | 266,8 → 16,9 мс | 2 → 0 |

p95 интервала кадра до и после — около 16,8 мс на всех аренах: исправления устраняют лишнюю работу и редкие задержки, а не повышают частоту выше 60 Гц. В итоговом запуске не наблюдались интервалы >33,4 мс. Это не гарантия отсутствия задержек на любом компьютере: короткий headless-прогон не заменяет длительную игру на физическом телефоне. Траектории немного различаются из-за реального `dt`, несмотря на одинаковый seed. Начальная загрузка, GPU-драйвер и другие приложения могут влиять на результат.

## Воспроизведение

Нужны доступные Node.js, Playwright и Microsoft Edge; при использовании внешнего пакета задать `NODE_PATH`.

```powershell
$env:PROFILE_HERO = 'automatix'
node tools/profile-combat.cjs docs/MICROFREEZE-repeat.json
node tools/trace-frame-stalls.cjs docs/MICROFREEZE-trace-repeat.json
```

`PROFILE_MAPS=camp` позволяет ограничить первый сценарий лагерем. Трассировщик сохраняет 60 самых долгих завершённых событий длительностью более 8 мс, а не полную трассу.

Сохранённые данные:

- `MICROFREEZE-before.json` — первичный замер до изменений, прежний сценарий без активации умений.
- `MICROFREEZE-abilities-before.json` — сравнимый сценарий с умениями до исправлений.
- `MICROFREEZE-abilities-after.json` — промежуточный результат после оптимизации HUD, до исправления дороги.
- `MICROFREEZE-final.json` — итоговый сценарий с обоими исправлениями.
- `MICROFREEZE-trace-before.json`, `MICROFREEZE-trace-after.json` — отдельные трассировки до и после исправления растеризации дороги; HUD уже оптимизирован в обеих.

## Регрессионные проверки

`tests/test-frame-work.cjs` проверяет отсутствие DOM-записей и копий сохранения при стабильном HUD, ограниченную частоту изменений таймеров/HP, немедленную реакцию на паузу, отсутствие маски на слое деталей, однократное наложение слоя и переиспользование кэша земли. Тест прогрессии проверяет отложенную запись ранга брони и сохранение при `pagehide`. Тесты способностей продолжают проверять все 12 умений.
