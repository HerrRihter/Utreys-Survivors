# Проверка вёрстки на экранах и устройствах

Этап 5 плана улучшения, блок «Вёрстка и устройства».

## Запуск

```bash
npm run build
npm run test:layout
```

Опции: `-- --quick` (4 размера), `-- --only phone-360,tablet`, `-- --screen hud,level-up`.
Без установленного Chromium Playwright скрипт берёт системный Edge; другой браузер задаётся
через `BROWSER_CHANNEL`. Скриншоты — `test-results/layout/<размер>/<экран>.png`, находки —
`test-results/layout/report.json`.

## Что проверяется

Экраны: меню, выбор героя, магазин, достижения, энциклопедия, настройки, HUD в бою (с
событием «инцидент»), левелап, пауза, настройки из паузы, итоги. Сохранение подставляется
с открытыми героями и одной победой, чтобы экраны были заполнены.

Размеры: телефоны 360×640, 390×844, 412×915 в портрете и ландшафте; планшет 768×1024 и
1024×768; 1366×768, 1920×1080, 2560×1440; масштаб интерфейса 80% и 130% на ноутбуке,
маленьком и обычном телефоне и планшете. Плотность пикселей 1–3, касание на телефонах и
планшетах.

На каждом экране:

- нет горизонтальной прокрутки страницы;
- каждый элемент управления прокручивается в зону видимости, не выходит за экран и сам
  находится под своим центром, то есть его ничто не перекрывает;
- на сенсорных экранах активные элементы не меньше 44×44 px, ползунки не ниже 22 px;
- подписи кнопок не обрезаны;
- в бою панели HUD не пересекаются и не выходят за экран, слоты сборки не вылезают из своей
  панели;
- в бою интерфейс закрывает не больше 30% экрана и не больше 8% круга вокруг героя (радиус —
  четверть меньшей стороны). Тост, подсказка и строка события временные: их доля выводится
  отдельно и не роняет проверку.

Повторяющиеся подписи кнопок на одном экране выводятся как предупреждения для ручного аудита.

## Найдено и исправлено (16.10)

| Проблема | Где | Исправление |
| --- | --- | --- |
| Кнопки звука и паузы под модальными окнами доступны с клавиатуры | все модальные экраны | `inert`, пока открыто окно |
| Кнопки меню меньше 44 px при масштабе 80% | сенсорные экраны | минимум `44px / масштаб` |
| Ползунки громкости, поле сида, выбор масштаба ниже 44 px | телефоны | то же |
| Верх длинных окон с кнопкой «Назад» обрезан | 130% на ноутбуке и планшете | `align-items: safe center` |
| «Доступен для забега» — неактивная кнопка без действия | магазин | заменена бейджем |
| Переключатели подписаны только «ВКЛ», награды — одинаково | настройки, достижения | `aria-label` с названием |
| Слоты сборки переносились в 2–3 ряда и наезжали на строку узлов | телефоны, планшеты | один ряд оружия, пассивки — на паузе |
| Строка узлов, событие и тост поверх героя | телефоны в ландшафте | строки внизу между умениями и стиком |
| Тост закрывал строку события | все размеры | тост ниже; на узком портрете — над кнопками умений |
| HUD при 130% закрывал до половины маленького экрана | телефоны | масштаб HUD до 100% (до 115% на телефонах шире 370 px); меню масштабируются полностью |
| Подписи стрелок обрезались краем, длинные имена узлов у героя | телефоны | подпись прижимается к экрану, имена сокращаются |
| Левелап 2×2 не помещался по высоте | телефоны в ландшафте | 4 компактные карточки в ряд |

## Замеры интерфейса в бою

После исправлений постоянный интерфейс не закрывает зону вокруг героя ни на одном размере.
Вместе с сообщениями (тост, событие, подсказка):

| Размер | Экран | У героя |
| --- | ---: | ---: |
| 360×640 | 27% (34%) | 0% (5%) |
| 640×360 | 25% (30%) | 0% (3%) |
| 390×844 | 19% (25%) | 0% |
| 844×390 | 17% (21%) | 0% (1%) |
| 768×1024 | 12% (14%) | 0% |
| 1366×768 | 15% (17%) | 0% (7%) |
| 1366×768, 130% | 25% (28%) | 0% (22%) |

На ноутбуке при 130% тост и строка события на время закрывают заметную часть зоны над героем.
Это допустимо для коротких сообщений, но если масштаб 130% популярен, стоит перенести тост
вниз и для широких экранов.

## Не проверяется автоматически

Видимый фокус и порядок Tab, жесты на реальном устройстве (джойстик, долгое касание),
системные выпадающие списки и экранная клавиатура при вводе сида. Это ручной проход на
Android Chrome и iOS Safari.
