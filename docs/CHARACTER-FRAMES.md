# Кадры персонажей

Анимации всех шести героев, трёх вариантов обычного римлянина, центуриона и пяти специальных отрядов используют отдельные PNG. Исходник списка кадров — `data/animations/character-frames.json`; его JS-копия обновляется командой `npm run generate`. Старые атласы сохранены как исходные материалы, но игра их не загружает и сборка Pages их не публикует.

## Размер и опорная точка

- Все анимационные PNG: **256 × 256**, RGBA 8 бит на канал, без чересстрочной развёртки, прозрачный фон.
- Стопы/контакт с землёй: **(128, 236)**. Центр персонажа по горизонтали — 128; последний видимый пиксель стоп обычно на строке 235.
- Отрисовка: один пиксель кадра соответствует одному логическому пикселю мира. Масштаб камеры применяется ко всей сцене.
- Во всех состояниях одного персонажа сохраняйте масштаб тела. Для ходьбы сохраняйте высоту стоящего персонажа; наклоны и приседания в атаке допускаются.
- Оружие входит в кадр полностью. Для новых рисунков оставляйте хотя бы 16 px по бокам и сверху; не растягивайте туловище под размер полотна.
- Изображения смотрят вправо. Левое направление создаётся зеркальным отражением вокруг общей точки опоры.

Размер PNG одинаковый, рост персонажей разный. Текущая видимая высота первого шага, включая головной убор/оружие:

| Персонаж | Высота, px |
| --- | ---: |
| Астерикс | 64 |
| Обеликс | 90 |
| Обычные римляне, три варианта | 77 / 66 / 82 |
| Центурион | 93 |
| Какафоникс / Антисанитарикс | 82 / 78 |
| Автоматикс / Панорамикс | 85 / 86 |
| Копейщик / метатель пилума / ветеран | 84 / 84 / 80 |
| Черепаха / таран | 106 / 122 |

Это сохранённые пропорции рисунков, а не размеры коллизий. Общая точка стоп устраняет скачки при переключении состояний. Таран занимает до 187 px по ширине, поэтому 128 × 128 недостаточно для общего стандарта без уменьшения тяжёлых отрядов.

## Редактирование и добавление

Кадры лежат в `assets/runtime/characters/<group>/<id>/animations/<action>/<index>.png`, где `<group>` — `heroes`, `enemies` или `civilians`, например `heroes/asterix/animations/walk/0.png`. Для изменения позы замените соответствующий PNG. Нарезать общий атлас или задавать прямоугольники обрезки больше не требуется.

В JSON каждый персонаж имеет `renderer` (`animation`, `villager` или `unit`), `actions` и `idle`. Пример:

```json
"new-hero": {
  "renderer": "villager",
  "actions": {
    "walk": ["characters/heroes/new-hero/animations/walk/0.png", "characters/heroes/new-hero/animations/walk/1.png"],
    "attack": ["characters/heroes/new-hero/animations/attack/0.png", "characters/heroes/new-hero/animations/attack/1.png"],
    "hurt": ["characters/heroes/new-hero/animations/hurt/0.png"]
  },
  "idle": {"action": "walk", "index": 0}
}
```

Порядок файлов в массиве — порядок воспроизведения. Число кадров может различаться по состояниям и персонажам. Ходьба зациклена; атака и реакция останавливаются на последнем кадре. `idle` ссылается на существующую позу, отдельная копия PNG не нужна. Если отдельной реакции нет, используется ходьба, как в прежней версии для Астерикса, Обеликса и центуриона. Момент нанесения урона задаётся игровой логикой, независимо от числа рисунков.

Если разные состояния нарисованы в разном масштабе, необязательный `actionScale` позволяет выровнять их один раз при загрузке. У Обеликса `"actionScale": {"attack": 1.1688311688311688}` приводит стоячую позу после броска с 77 к 90 px; этот же коэффициент применяется ко всем четырём кадрам атаки вокруг точки стоп. Согнутая поза при поднятии менгира остаётся ниже стоячей. Покой использует кадр `attack/3.png`, где персонаж стоит прямо. Нормализованные кадры кешируются; масштабирование не выполняется в игровом цикле.

Новые наборы автоматически подключаются к выбранному адаптеру отрисовки и списку публикации. Чтобы сделать персонажа доступным в игре, отдельно добавьте его параметры и поведение в игровой список героев/врагов. Анимационный загрузчик менять не требуется.

После изменений: `npm run generate`, `npm test`, `npm run build`. Просмотр всех кадров: `previews/animation-audit.html`; просмотр движения героев: `previews/animation-preview.html`.

Карточки разведданных автоматически подбирают масштаб по общей видимой области всех кадров персонажа. `npm run generate` считывает прозрачность PNG и обновляет `data/animations/character-bounds.js`, учитывая `actionScale`. Поэтому запускайте генерацию и после замены рисунков без изменения JSON. Масштаб карточки остаётся одинаковым при переключении состояний и развороте; широкие отряды уменьшаются с запасом до краёв, небольшие фигуры увеличиваются максимум в 1,6 раза. Во время показа карточек чтение пикселей не требуется, включая запуск через `file://`.

## Производительность

Один PNG декодируется один раз на набор персонажа и переиспользуется всеми его экземплярами. Переключение кадра выбирает изображение из кеша; во время боя нет создания Image/Canvas, нарезки атласов или сетевых запросов. Полный набор из 168 кадров занимает примерно **42 MiB** декодированных RGBA-пикселей (без накладных расходов браузера). Дополнительные враги не создают копии этих изображений.

Проверка на этой машине в headless Edge 155, локальный HTTP, 300 рисунков за такт, 120 тактов, медиана семи измерений после двух разогревов:

| Измерение | До | После |
| --- | ---: | ---: |
| Отрисовка + принудительное завершение Canvas, ms/такт | 67,91 | 7,92 |
| Передача ресурсов страницы проверки | 31,27 MB | 3,82 MB |
| Число запросов страницы проверки | 76 | 178 |
| Готовность страницы, один холодный запуск | 720 ms | 858 ms |

Скрипт: `tools/benchmark-character-frames.cjs`; результаты: `FRAME-BENCHMARK-BEFORE.json` и `FRAME-BENCHMARK-AFTER.json`. Проверка включает `getImageData` после каждого такта, чтобы браузер завершал отложенные команды Canvas. Она сравнивает старые Canvas-кадры и новые Image-кадры, а не полный игровой FPS. Разброс измерений до изменения заметный, поэтому цифры не следует трактовать как обещание восьмикратного ускорения игры.

Замедления отрисовки на этой машине не обнаружено. Главный компромисс — больше запросов при первом открытии. На сети с высокой задержкой начальная загрузка может быть медленнее; проверка на локальном сервере не измеряет мобильную сеть или реальный GitHub Pages. Размер опубликованного сайта уменьшился с 45,41 до 16,63 MB. Дальнейшее увеличение количества персонажей потребует оценки памяти и, при необходимости, загрузки наборов по выбранной карте.
