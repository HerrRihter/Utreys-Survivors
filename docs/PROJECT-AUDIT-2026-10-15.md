# Аудит проекта и план приведения к единому состоянию

Дата: 15 октября 2026 года. Объект: текущая рабочая копия Utreys Survivors.

## Вывод

Главная проблема — незавершённая миграция. React/Vite и новый контент Utrace уже стали основным приложением, но публикация, большая часть тестов, загрузчики арта, генераторы и техническая документация всё ещё обслуживают предыдущую игру. Простое удаление «старых» папок сейчас сломает импорты и проверки.

Рекомендуемая целевая версия: текущая игра Utrace, одна арена `empty`, пять противников, React-интерфейс и Vite-сборка. Это рабочая предпосылка плана на основе README и действующих данных, а не предложение восстановить старых героев ради прохождения тестов. Если прежняя игра должна оставаться поддерживаемым продуктом, ей нужен отдельный пакет/ветка и собственные проверки.

В рамках аудита код и ресурсы не исправлялись и не удалялись. Добавлен только этот отчёт.

## Объём проверки и ограничения

Проверены структура отслеживаемых файлов, конфигурация запуска и публикации, точки входа, жизненный цикл сессии, игровые данные, основные системы, React-компоненты, CSS, реестры ресурсов, генераторы, тесты и документация. Все 27 верхнеуровневых тестовых файлов запускались отдельно; дополнительно выполнены проверки контрактов, генерации и небольшой smoke-сценарий сессии через существующий harness. Дубликаты ресурсов сравнивались по SHA-256.

Это аудит исходников и локальных автоматизированных проверок. Браузерная визуальная проверка, прохождение полного забега, измерение production-загрузки и производительности на устройствах не выполнены. `npm run build` и `npm run lint` запускались, но остановились из-за отсутствующих локальных `vite` и `tsc`: `node_modules` отсутствует. Это ограничение среды, а не доказательство ошибки компиляции. Установка и проверка доступности заявленных версий пакетов не выполнялись; уязвимости зависимостей и юридические права на ресурсы не проверялись.

### Воспроизведение жизненного цикла

Через существующий `tests/helpers/game-harness.cjs` создана сессия, запущена и остановлена; затем повторено создание/запуск/остановка. При учёте всех регистраций получены: resize — 2, каждый из трёх art-ready — 2, keyup/blur — по 2, keydown — 4, visibilitychange — 4, pointerdown на глобальной поверхности — 2. Cleanup этих регистраций в stop отсутствует. Это подтверждает накопление слушателей; конкретное поведение двойных нажатий в настоящем браузере ещё следует проверить. Текущий harness хранит по одному handler на событие и сам по себе маскирует этот класс ошибок.

## Целевая структура и правила

Сохранить уже полезное разделение `src/app`, `core`, `systems`, `world`, `rendering`, `data`, `tools`, `tests`, `assets/source`. Не начинать ещё одну тотальную перестановку папок.

```text
src/main.tsx                 единственный production bootstrap
src/app/                    сессия, её lifecycle, адаптер React ↔ engine
src/components/             React-экраны и общие UI-компоненты
src/core/                   время, ввод, звук, математика
src/systems/                механика с явными зависимостями
src/world/                  актуальная арена, геометрия и навигация
src/rendering/              Canvas, загрузка активных ресурсов
data/                       единственные определения игрового контента
styles/                     токены, общие стили, стили компонентов
assets/runtime/             только поддерживаемые игровые ресурсы
assets/source/              материалы изготовления, вне публикации
previews/                   поддерживаемые dev-страницы
tests/                      актуальные проверки + helpers
tools/                      воспроизводимые генераторы и проверки
docs/                       актуальные инструкции и индекс
docs/archive/               исторические планы и аудиты
docs/benchmarks/             сценарии и датированные результаты
dist/                       генерируется Vite, не хранится в Git
```

Публикация `assets/runtime` должна быть реализована явно: либо импорты, которые сборщик видит, либо копирование только активного набора с базовым URL. Не создавать две вручную редактируемые копии assets и public. Если сохраняются JSON→JS производные, каждый файл должен иметь первичный источник, команду генерации и проверку актуальности.

Правила консистентности:

- Идентификаторы контента определяются в data; UI не поддерживает параллельный ручной список вроде ALL_UNIT_KEYS. Числа HP/скорости/времени появления в описаниях выводятся из тех же определений.
- Сессия имеет явные start/pause/resume/stop/dispose; скрытая React-панель не должна получать игровой ввод, а поведение фонового RAF задаётся сознательно.
- React владеет своими элементами; engine получает canvas, адаптер UI и сервисы. Не добавлять новые обращения к глобальному DOM в игровых системах.
- Семантические токены: background/surface/text/muted/border/accent/danger/reward; одинаковые кнопки, отступы, диалоги, фокус и типографика во всех экранах.
- Стиль кода фиксируется инструментами: единый формат, порядок импортов и правила unused. Массовое форматирование делать отдельно от функциональных изменений.
- Контракт структуры проверяет существование файлов, актуальность производных и набор публикации; contract-валидаторы проверяют определения героя, врагов, карт, апгрейдов и достижений.
- Изменения storage-формата версионируются и мигрируются; старые имена ключей не заменяются механическим поиском.

## План работ с критериями приёмки

### Этап 1. Воспроизводимая проверка и поставка — P0

1. Зафиксировать текущую продуктовую границу и поддерживаемые способы запуска в README/контракте.
2. Установить и проверить зависимости, создать lockfile, задать Node/npm и дополнить gitignore.
3. Согласовать npm-команды и CI; добавить PR-проверки, публиковать только после успешных проверок. Убрать старую rollback-ветку из автоматической публикации, если она больше не предназначена для релизов.
4. Согласовать Vite, пути ресурсов, base и production entry; проверить запуск как в корне домена, так и под префиксом репозитория.

Приёмка: свежая копия проходит `npm ci`, typecheck, актуальные tests и build; CI использует те же команды; из production-артефакта запускается React-приложение, все активные ресурсы возвращают 200, source/docs/tests не публикуются. До выполнения этого этапа готовность к публикации не подтверждена.

### Этап 2. Корректный lifecycle и минимальное покрытие — P1

Приёмка: все заявленные актуальные проверки зелёные; нет скрытых падений за сокращённым npm test, утечек handlers/RAF, двойного ввода и расхождения preview с механикой. Отдельно проверены отказ localStorage и испорченные сохранения.

## Чего не следует делать

- Не восстанавливать всю старую игру для удовлетворения устаревших assertions.
- Не удалять папки по историческим названиям, пока они импортируются активным приложением.
- Не отключать StrictMode как исправление lifecycle и не считать отсутствие ошибок harness доказательством отсутствия утечек.
- Не смешивать форматирование, переименование, миграцию сохранений и изменение баланса в одном изменении.
- Не объявлять Vite-сборку, мобильный интерфейс или производительность проверенными до реального запуска соответствующих проверок.
