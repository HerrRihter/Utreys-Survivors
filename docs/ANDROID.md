# Android: APK файлом, без Google Play

Игра упакована в приложение через [Capacitor](https://capacitorjs.com): собранный `dist/`
лежит внутри APK и открывается в WebView с адреса `https://localhost`. Сеть нужна только для
облака: вход, синхронизация прогресса (`progress/{uid}`) и таблицы. Без сети игра работает как
обычно, прогресс и забеги ждут в localStorage и уходят, как только сеть появится (событие
`online` в `src/app/useGameSession.ts`, иначе повтор раз в минуту).

Проект Android — папка `android/` (создана `npx cap add android`, коммитится). Копия игры
(`android/app/src/main/assets/public`) и сборки Gradle в git не попадают.

## Один раз: окружение

1. Установить **Android Studio** и один раз открыть её: мастер первого запуска скачает
   Android SDK в `%LOCALAPPDATA%\Android\Sdk`. Свой JDK не нужен: скрипт берёт встроенный
   в Android Studio (`jbr`, Java 25), если `JAVA_HOME` не задан. Поэтому Gradle wrapper
   поднят до 9.1 (8.x шаблона Capacitor на Java 25 не запускается), а Java получает свою
   временную папку `android/.gradle/java-tmp` (иначе на Windows бывает «Unable to establish
   loopback connection»).
2. `.env.local` с `VITE_FIREBASE_*` — тот же, что для сайта ([FIREBASE-SETUP](FIREBASE-SETUP.md)).
   `VITE_FIREBASE_EMULATOR` при сборке APK должен быть пустым: скрипт это проверяет.

## Сборка

```powershell
npm run android:apk
```

Собирает игру, копирует её в `android/` и делает debug-APK:
`android/app/build/outputs/apk/debug/app-debug.apk`. Он подписан отладочным ключом этого
компьютера: годится, чтобы проверить на своём телефоне (`adb install -r <apk>` или скопировать
файл и открыть).

`npm run android:open` открывает проект в Android Studio (эмулятор, отладка, Logcat).
WebView отлаживается из Chrome на ПК: `chrome://inspect` при подключённом по USB телефоне с
включённой отладкой.

## Подпись: APK для раздачи

Android ставит обновление поверх, только если оно подписано **тем же ключом**. Поэтому для
раздачи один раз создаётся свой ключ, и все версии подписываются им. Потеряете ключ — игрокам
придётся удалить приложение (и локальный прогресс; облачный останется) и поставить заново.

1. Создать ключ (keytool лежит в JDK Android Studio):

   ```powershell
   & 'C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe' -genkeypair -v -keystore android\release.jks -alias utreys -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Создать `android/keystore.properties`:

   ```properties
   storeFile=release.jks
   storePassword=<пароль хранилища>
   keyAlias=utreys
   keyPassword=<пароль ключа>
   ```

   Оба файла в `.gitignore`. Сделайте резервную копию `release.jks` и паролей вне репозитория.

3. Собрать:

   ```powershell
   npm run android:apk -- release
   ```

   Готовый файл — `android/app/build/outputs/apk/release/app-release.apk`. Перед новой
   версией увеличьте `versionCode` (и `versionName`) в `android/app/build.gradle`.

Игроку: разрешить установку из неизвестных источников для приложения, которым он открывает
файл (браузер, «Файлы», Telegram), и открыть APK.

## Поведение в приложении

- Полный экран: системные панели скрыты, появляются на время свайпом от края
  (`MainActivity.java`).
- Кнопка «Назад» работает как Escape: закрывает экран меню или ставит забег на паузу и
  снимает с неё (`src/services/native-app.js`). Выйти из игры — кнопкой «Домой» или из
  списка приложений.
- Сворачивание ставит забег на паузу и сохраняет прогресс, как уход со вкладки в браузере.
- Ориентация не закреплена: вёрстка рассчитана и на портрет, и на ландшафт.
- Удаление приложения стирает локальный прогресс. Вошедший игрок вернёт его из облака.

## Защита облака

Ключи Firebase в APK не секретны: их можно достать из любого клиента, и это нормально.
Базу защищают правила `firestore.rules`, а не скрытность ключа:

- игрок читает и пишет только свой прогресс и свою статистику, чужое — только таблицы на чтение;
- прогресс — только поля сохранения игры с типами и пределами, статистика — только рост в
  разумных пределах, удалять нельзя ничего;
- забаненный (`npm run admin:ban`) не может записать ничего.

Чего правила не запрещают: игрок может записать себе накрученный прогресс или рекорд в
пределах лимитов — игра целиком на телефоне. Против этого — бан и чистка таблиц.
App Check не используется: без Google Play его проверка (Play Integrity) для APK из файла
не работает. Квоты и ограничение API-ключа — [FIREBASE-SETUP](FIREBASE-SETUP.md), «Защита и квоты».

## Проверка на телефоне

- Первый запуск в авиарежиме: меню, забег, стик, звук после первого касания.
- Вход в аккаунт, забег, закрыть приложение, открыть: вход и прогресс на месте.
- Забег без сети, включить сеть: прогресс и строка в таблице появились без перезапуска.
- Два устройства с одним аккаунтом: диалог выбора сохранения.
- «Назад» в меню и в забеге, сворачивание посреди забега, поворот экрана.
