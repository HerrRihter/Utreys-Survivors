# Utrace Survivors

Браузерная survival arena на React, TypeScript, Canvas и Vite: пять модификаций героя Utrace, арена дата-центра, 16 противников и пять багов-минибоссов, активные умения Q/E, улучшения и локальные сохранения.

## Разработка

Требуется Node.js 22 или новее. Версии пакетов закреплены в package-lock.json.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Прямой запуск index.html через file:// не поддерживается.

## Проверки и сборка

```sh
npm run check
npx playwright install chromium
npm run test:browser
```

check выполняет линт JavaScript, строгую проверку TypeScript, проверку форматирования, все тесты, контракты и production-сборку. test:browser проверяет уже собранный dist. На Windows можно использовать установленный Edge: `$env:BROWSER_CHANNEL='msedge'; npm.cmd run test:browser`. Если PowerShell блокирует npm.ps1, используйте npm.cmd вместо npm.

- `npm test` — все тесты (vitest, tests/*.test.js).
- `npm run format` — форматирование исходников.
- `npm run check:structure` — проверка структуры и ресурсов.
- `npm run build` — сборка в dist.
- `npm run preview` — просмотр production-сборки на порту 3000 (через тот же `preview()` Vite smoke и layout открывают dist).

GitHub Actions выполняет те же проверки и браузерный smoke для PR. Публикация dist в GitHub Pages выполняется только для main/master и ручного запуска, после проверок.

## Навигация

Основная игра — `/`, просмотр арены — `/?view=arena`, противники — `/?view=opponents`. С `?dev` в адресе появляются инструменты разработчика: журнал забегов в настройках, управление анимацией в бестиарии и границы коллизий на странице арены. Старые адреса opponents-preview.html и arena-preview.html перенаправляют на соответствующие экраны.

[Техническая документация](documentation.md) · [Контракт структуры](docs/STRUCTURE-CONTRACT.md) · [Индекс документов](docs/README.md)

Цель забега: освободить пять узлов компонентов, уничтожая охраняющих их багов или находя воркэраунды. Для воркэраунда оставайтесь в круге узла 6 секунд без урона; выход сбрасывает поиск. После разрешения всех узлов появляется ЦРПТ, его поражение завершает забег победой. Таймер появления босса и обязательное ожидание пяти минут отменены.

## Эскалация инцидента

В выборе карты доступен экспериментальный «Ситуационный центр». Сначала рекомендуется
пройти курс «Управление критическими инцидентами» в учебном центре.

1. Начните смену и следите за табло шести компонентов, потоком документов и алертами.
2. Расчистите место вокруг героя и откройте «Пульт» (на телефоне — ☎). На пульте бой
   и часы смены остановлены. Выберите компонент, начните эскалацию и заведите тикет.
3. Заполните карточку, определите критичность, вызовите команду по матрице, отправляйте
   сообщения и фиксируйте действия в журнале трекера. Во вкладке «Памятка» есть материал курса.
4. Закажите метрику, вернитесь в бой и победите нужных противников за указанное время.
   Снова откройте пульт, чтобы прочитать график. Обрабатывайте входящие вводные.
5. Доиграйте смену и ответьте на вопросы разбора PIR: появится оценка с ошибками,
   правильными ответами и пояснениями курса. Смерть героя или обвал срывают смену.

После перезагрузки страницы нажмите «Продолжить забег»: смена восстановится на паузе,
включая тикеты и заказанные метрики. Смена не входит в рейтинг, рекорды и статистику баланса
и не открывает продакшен. Её сводка сохраняется в локальном журнале забегов.

Браузерный сценарий смены — `tools/incident-browser.cjs`, входит в `npm run test:browser`.
Правила и статус реализации — [план режима](docs/INCIDENT-ESCALATION-PLAN.md).
